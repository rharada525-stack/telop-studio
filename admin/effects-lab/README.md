# 演出ラボ（ローカル管理者用）

別PCへの引き継ぎは [00_ここから読む.txt](handoff/20261023/00_ここから読む.txt) から開始してください。GitHubへの送信状況・Premiere検証データ・ブラウザ保存JSONの復元方法をまとめています。

PowerShellで `./admin/effects-lab/Start-Lab.ps1` を実行し、表示されたURLを開きます。Python 3が必要です。
標準URL: `http://127.0.0.1:8767/admin/effects-lab/`。終了はサーバーの画面で Ctrl+C。

- 左から演出を選び、再生・0.25/0.5倍速・1コマ送りで登場と退場を確認。
- 縦横、デザインセット、演出の文字、通常字幕、位置、画面効果を切り替えられます。
- 「元と比較」で、同じ時刻・背景の本体版と試作を並べます。音は試作側だけです。
- パーツを選び、文字サイズ・動き・傾きやスタイルJSONを調整。縦と横の調整は別々に保持します。
- 「試作を保存」はラボ専用のブラウザ保存。編集中の試作も自動で復元します。背景の画像・動画は保存しません。
- 保存済みの試作を読み込んで保存すると上書き。「別の試作として保存」で調整中の内容を別枠に残せます。「新しい試作」は初期状態から開始。
- 「JSONに保存」でバックアップ・受け渡し。「JSONを読み込む」で続きから再開。PNGは現在のフレーム（ガイドなし）。
- 動画の背景は音声を出さずに再生します。動画の開始位置も指定できます。低速時の効果音はタイミングだけ同期し、音程は変えません。

## 本体との関係

`telop-studio/js/render.js`、`telop.js`、`timeline.js`、`sets.js`、`styles.json`、`sfx/` を直接使います。
本体の演出一覧に種類を追加すればラボにも出ます。新しい文字スタイルや動きの試作は、ここで比較してから本体へ反映します。
見出しは全体・ラベル・本文を別々に選べます。画面効果の動き自体は本体のRendererで管理し、ラボでは組み合わせを試します。

ラボは公開対象の `telop-studio/` の**外**にあり、GitHub Pagesの成果物に入りません。
編集画面のリンク、プロジェクト保存、字幕の標準設定、AIモデルにも触れません。
ローカルホスト以外では起動しない補助チェックもありますが、認証の代わりではありません。
リポジトリ自体の公開範囲は変えません。将来オンラインで管理する場合は、別途認証付きの配置が必要です。

## Premiere用テキストXML

2026-10-22にユーザーのPremiereで、PostScript名を指定したFCP 7 Text generatorの読み込み・フォント表示・文字編集を確認済みです。
2026-10-23には、Premiere 2026の別の検証用プロジェクトで、フチ付きのGraphicAndType XMLの表示・文字書き換え・Undo/Redo・保存と、登場の拡大・不透明度変化を実機確認しました。元のユーザープロジェクトは変更・保存していません。

一覧上部の［XML］付きは15種類の動きです。ポップ・スラム・左スライド・バウンド・落下・ふわっと登場・ズームイン・下からスライドに、光が左から走る・星が弾ける・星が降ってくる・二度弾けるお祝いスター・宝石のきらめき・文字に光が走る・光と宝石のフィナーレがあります。
「二度弾けるお祝いスター」は大小12個ずつの星が2回弾けます。「宝石のきらめき」は周囲8か所を3巡し、それぞれの星が二度輝きます。どちらも最大24個の星で、本文の読みやすさを保つため文字の範囲へ重なる軌道は空いている辺へ移します。
「文字に光が走る」は本文の表面を光沢の帯が1回横切ります。「光と宝石のフィナーレ」は2回の光沢と周囲の星を組み合わせます。「文字表面の光」欄で1回・2回・なしを切り替えられます。

「デザインを選ぶ」で王道イエロー・リッチゴールド・ルビーレッド・アイスブルー・エメラルド・ロイヤルパープル・キャンディピンク・パールホワイトを切り替えます。動き・文章・時間・配置を保ったまま比較できます。塗りの縦グラデーションに加え、ゴールドとパールはフチにもグラデーションを使います。

用途別に、書体・大きさ・フチの構成が異なる14案も選べます。「豪華」で5案、「ツッコミ」「見出し」「締め」で3案ずつ、「共通」で従来の8案、「すべて」で22案を表示します。

| 用途 | デザイン |
| --- | --- |
| 豪華 | プレミアムゴールド（極太ゴシック・濃淡の金属光沢）、白金の祝福（極太明朝・白金と金のフチ）、ロゼの余韻（明朝・温かい金属光沢）、シャンパンの祝宴（明るい金の明朝・4層フチ）、クリスタルの輝き（端正なゴシック・白金の3層フチ） |
| ツッコミ | 白抜き・ド迫力（極太・赤の太い二重フチ）、真顔のひとこと（明朝・黒字に細い白フチ）、ビックリ警報（明暗の強い4層フチ） |
| 見出し | 章タイトル（明朝・細い金フチ）、ニュース見出し（ゴシック・太い紺フチ）、特集・モノクロ（太字・白黒の二重フチ） |
| 締め | グランドフィナーレ（大きな明朝・金属の4層フチ）、余韻のありがとう（小ぶりな明朝・細い二重フチ）、次の一歩へ（極太ゴシック・白フチ） |

用途別の案を選ぶと推奨書体と縦横別のサイズも適用します。書体・サイズは選択後に調整できます。文章は保持し、「見本に戻す」で用途に合う文例を表示します。

標準の傾きは0度。横長の「おまかせ」は下中央（1920×1080では960,900）です。位置を明示した場合はその指定を優先します。
書体はプレビューとXMLに同じ指定を使います。PCフォントから選んだ場合も実際のPostScript名を保持します。

- 「この演出をXMLに保存」: 調整中の1案。
- 「動き15案のXMLを保存」: 選択中のデザイン・書体で15の動きを4秒間隔に配置。
- 「この動き × 豪華5案のXML」など: 表示中の用途の候補を、調整中の文字・動き・時間で比較。各案の推奨書体を個別に保持。「すべて」では22案を書き出します。
- 「この動きの標準にする」: このPCのラボだけに、動き別のデザイン・書体・見た目の調整を保存。次に動きを選ぶと適用。公開版の設定は変更しません。
- 「標準指定を解除」で元の選択動作に戻せます。「標準指定をJSONに保存」で持ち出し、「JSONを読み込む」で戻せます。

30fpsのFCP 7 XML（xmeml version 5）です。
フチまたはグラデーション付きの場合は、Premiere自身がXMLに書き出すGraphicAndTypeのSource Textデータを生成します。1クリップ内の1文字レイヤーが色・多重フチを持つため、Premiereで一度文字を書き換えれば装飾にも反映されます。フチを文字の複製で作る方式ではありません。
光沢なし・フチなしの単色の場合は従来のText generatorを使い、検証済みの読み込み経路を残します。
動きはBasic Motion（位置・拡大率・回転）とOpacityのキーフレームです。
キラキラは本文と別トラックの星の文字（Segoe UI Symbol / `SegoeUISymbol`）です。本文はV1の単一文字レイヤーを保ち、星をV2以降へ最大24本の装飾トラックとして配置します。画像や動画は使いません。`sparkles.mjs`の同じ30fps値をプレビューとXMLで使い、逆方向シークでも同じ表示になります。星は本文のフチを含む範囲を避けて配置します。Premiereで本文の幅や位置を変えた場合は、星の位置も必要に応じて調整してください。
新しい豪華演出は初めて選ぶ時だけ推奨デザインを適用し、指定済みの標準があればそちらを優先します。デザインや書体を変えてもキラキラの種類は保持され、「キラキラ」欄から変更・解除できます。
文字表面の光は、本文1個を共有するシーケンスを原色と光沢の2層で参照し、光沢側だけをCropとScreenで合成します。Premiereではプロジェクトパネルの「本文を編集_…」シーケンスを開き、文字を1か所で変更すると両方へ反映されます。本文全体の移動・拡大・退場は外側のクリップで調整できます。文章の幅を大きく変えた場合は、光沢帯のCropキーフレームも調整が必要になることがあります。文字画像・動画を生成する方式ではありません。
光沢の位置と強度は`surface-light.mjs`の同じ30fps値をプレビューとXMLで使います。デザイン・書体を変更しても光沢の種類は保持され、標準デザインの保存には光沢の種類を混ぜません。
CanvasとXMLは `block-motion.js` の同じ計算を使います。一定区間の中間キーだけを省き、停止開始・再開時刻を残します。
長文を縮小した場合はRendererが実際に使った文字サイズと配置を渡します。
Source Textは文字サイズを直接指定し、Canvasのベースライン（高さsizeの0.88）と中央との差を補正します。Text generatorではPremiereの480行基準のサイズ倍率を補正します。

Source Textのバイナリ形式は公開仕様ではありません。Premiereのバージョンを更新した場合は、取り込み・文字編集・装飾と動き・保存後の再読み込みを再確認してください。
追加の実機確認では、横長・Noto Sans JP Blackの金色5色グラデーション、青色4色グラデーション、金色の追加フチを表示し、金色の文字を書き換えて装飾が保たれることと保存を確認しました。ブラウザとPremiereは字面の範囲の取り方が異なるため、グラデーションの位置は多少異なる場合があります。
ブラウザで書き出したNoto Serif JP Blackのデザイン8案も読み込み、ゴールドの4本フチ・塗りを保持した文字編集と保存を確認しました。
今回の実機確認は横長・Noto Sans JP Black / Noto Serif JP Blackです。縦長、それ以外の書体、各動きの全フレーム一致、プロジェクトを閉じて再読み込みする操作は未確認です。
用途別9案の追加後は、ブラウザで全9案の切替・書体・サイズ・XML出力を確認し、実際のダウンロードXMLの17クリップ・5書体・各1文字レイヤー・時刻を再解釈して確認しました。自動テスト98件も成功。追加9案のPremiere実機再確認は、再起動後の操作ツールが起動画面をアクティブにできず未完了です（`failed to activate captured window`）。既存形式の実機結果と、新案の構造検証を区別してください。

影・背景プレート・複合パーツ・縦書き・字間・1文字ずつ・ワイプ・非等方の変形・一部だけの強調・複数行は対応していません。塗りとフチは単色または上から下への2〜8色の線形グラデーションに対応。フチは0〜80px、4本までです。角度付き・円形・透明度付きのグラデーションは未対応です。該当する場合は理由を表示して保存を止めます。
既存の試作のJSON・保存データは引き続き使えます。標準デザインの変更は、保存済みの個別のスタイル指定を上書きしません。
**XMLに通常字幕・背景・画面効果・効果音は含みません。画像・MP4・MOGRTへの置き換えは行いません。**

フォントは「書体」またはPCのフォントから選びます（初期値 `NotoSansJP-Black`）。XMLに渡すPostScript名は「書き出すフォント」で確認できます。フォント本体は同梱しません。

## Premiere標準の光とネオン

ネオンワイプ／ライトスイープはPremiere 26.0以降の標準トランジションを使います。このPCでのFCP 7 XML書き出しでは両方ともクロスディゾルブへ変換され、変換ログにも非対応と記録されました。文字用XMLは維持し、標準の光とネオンは別のプロジェクトで受け渡します。

[サンプルプロジェクト](samples/premiere-native-light.prproj)はPremiere本体の「選択範囲をPremiereプロジェクトとして書き出し」で保存したものです。ブラウザで.prprojを生成する機能ではありません。横長の1シーケンスに、各1文字レイヤーの本文2個と、それぞれの冒頭に標準トランジションを配置しています。外部の動画・画像・MOGRTは不要です。書体はPCにNoto Sans JP Blackが必要です。

サンプルをPremiereで開くか読み込み、文字を変更して使えます。既存のXML字幕へ演出だけ追加する場合は、サンプルのトランジションをコピーし、対象字幕の冒頭の編集点へ貼り付けます。

Premiere 2026で配布サンプルを再度開き、1シーケンス・本文2個の読み込みを確認しました。「ネオンの光で登場」を「きらめく文字に変更」へ書き換え、00:00:01:02で新しい文字にもネオンワイプが適用されることと、Ctrl+Zで元の文面へ戻ることを確認済みです。配布ファイルは変更していません。ラボのダウンロードファイルが配布元と同じ内容であることもSHA-256で確認しました。ライトスイープ側の文字変更と、別のXML字幕へトランジションをコピーする操作はまだ実機未確認です。
